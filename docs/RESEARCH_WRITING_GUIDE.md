# 科研写作：让读者先读懂问题与判断

这份指南适用于研究灵感、预研报告、文献分析和论文正文。目标是让读者准确理解内容，不是模仿聊天腔，也不是规避 AI 检测。

## 1. 先决定读者需要知道什么

写之前先确定：读者读完这一段，应当明白什么，或者能够作出什么判断。研究灵感需要讲清问题、切入点和价值；文献分析需要说明已有工作做到了哪里；结果段需要交代观察及其含义；方法和复现文档才需要详细步骤。

调查可以深入，交付不必回放调查。找到五篇相关论文，不等于正文必须依次介绍五篇。执行过检查，不等于需要写一段“经过检查，因此可信”。读者需要的是检查后留下的认识。

一段通常承担一个主要任务，但可以包含相互依赖的解释、例子和条件。不要把“每句只做一件事”理解成切碎所有复句。先说明对象和动作，再解释关系，保留自然的因果、转折与承接。Gopen 与 Swan 的写作讨论强调读者如何依靠句子结构理解内容，而不是只靠更换词汇。[S1]

## 2. 区分必要的边界与防御性话语

必要边界决定一句话到底说了什么。例如“在相同推理预算下”“仅有摘要可读”“这一解释尚未验证”。删掉它们可能改变比较对象、证据强度或适用范围。

防御性话语主要是在向读者表态，例如“尽管仍有诸多不足，但不能因此否认其潜在价值”“需要强调，我们并非声称解决了所有问题”。这些句子常常没有提供新的判断依据。

判断方法是：删掉这句话，读者会不会把假设当结果，把局部结论当普遍结论，或误判现在能不能做？会，就保留它的具体信息；不会，而且前文已经说过，就删除或合并。

不把“可能、尚未、在……条件下”列入禁词表。该确定的事实直接写，该保留的未知具体写。Manchester Academic Phrasebank 将谨慎措辞用于不确定解释和避免过度概括；这不要求每段都以限制声明收尾。[S2]

原文已经给出的定理前提、实验范围、未测范围，不因润色而消失。重要前提贴近对应结论；完整但次要的枚举可移到明确标注的范围说明。页面可以分层，结论不能变成无条件承诺。仅删去“尚不能外推”而不保留实际范围，并不一定是好的改写。

## 3. 用具体判断代替自我辩护

不要写“虽然没有完整证明，但仍具有一定意义”。写清楚这件事为什么值得继续：它可能解释什么失败，改变什么设计选择，或者为哪个真实需求提供新的处理方式。

不要写“受限于当前材料，我们尚不能作出完全充分的判断”。写“这篇近邻目前只有摘要，尚不清楚它是否已经做过同样的比较”。前者只有态度，后者告诉读者缺什么。

对事实、作者解释、自己的推测和未来计划，选择相应动词。文献“报告”了什么；现有材料“提示”什么；本想法“猜想”什么；后续研究“将比较”什么。不要把它们都写成“验证了”，也不要把已知事实一律弱化成“似乎可能”。

## 4. 正文讲研究内容，记录页讲操作过程

“本轮”“已接受”“复核通过”“证据绑定”“未触发恢复”“不改变预算”等内容各有用处，但通常属于运行记录、费用页或修改记录。把它们移走后，正文仍应说明影响选题的实际结果：哪项前提被推翻、哪条近邻覆盖了原想法、现在还剩下什么。

科学边界与操作状态要分开。全文没拿到，可以写“该近邻的覆盖范围仍待查”；不必展开每次 HTTP 错误。预算暂停可以说明“预研尚未完成”，不能写成“想法不成立”。同样，流程完成不能写成“方案已经可靠”。

如果用户正在排查工具故障，操作记录就是正文。信息放在哪里取决于文档用途，不实行全局删词。

## 5. 让段落前进，而不是不断补充

优先形成这样的阅读顺序：具体问题是什么；候选看到了什么不同的解释或做法；已有材料为何让它值得考虑；现在最需要弄清什么。顺序可以随题目调整，不要求每张卡使用完全相同的四个标题。

先讲人、模型或系统在做什么，再引入必要术语。把“环境驱动的描述漂移导致检索失配”写成“环境变了，技能描述还停留在旧场景，系统可能因此找不到本来能用的技能”。需要讨论技术实现时，再解释“描述漂移”和检索索引。

长短句可以交替。不要连续使用名词堆叠、斜杠、加号、括号和分号把一整套方案塞进一个句子。也不要改成“一句话一段”的断裂口号。一个例子能够帮助读懂时就保留；只有一句漂亮结尾、没有新信息时就删去。

## 6. 预研报告不要替人写实验说明书

预研阶段说明可行路径即可：准备使用什么已有模型、资料或接口，做哪个主要操作，面临什么关键困难。未来检验通常用一两句话说明它能区分什么，不展开所有参数、分组、种子、检验阈值和异常分支。

这不是拒绝技术细节。一个方法为什么可能有效，需要讲清；一个关键条件不成立会使结论失效，也需要讲清。只是不要为了显得周全，把每项普通实现选择都写成开工前的验收条款。

当原始技术材料已经包含这些细节时，可以在详细记录中保存。正文既不能照抄全部，也不能把有前提的路径缩成“直接实现即可”。

## 7. 不用“首次”“完全空白”替代新意

更有用的比较是：“已有工作更新技能代码，这个想法关注代码仍然适用、但检索描述已经过时的情况。”这比“首次构建环境感知的多维技能维护框架”更容易让人理解和质疑。

写清近邻具体解决了哪部分，候选准备多回答哪个问题。材料只到摘要，就按摘要能够支持的范围介绍。不要用“已检范围内”给一个实质上仍然过强的“世界首次”结论加保险。

大胆提出假设与准确描述文献可以同时做到。新想法没有实验，不是需要道歉的事情；已知前提为假，也不能靠把语气改成“可能”保住它。

## 8. 少给重复任务，多给一个真实目标

“自然、简短、严谨、不啰嗦、口语化、不防御”叠在一起，仍然没有说明该怎么写。更具体的指令是：“写给了解大模型、但不了解这个细分题目的同事。先让他明白这个想法解决什么问题，再解释最关键的文献差异和未知。”

社区讨论反复出现“已经加入很多简洁指令，回复仍很长”的反馈，也有人建议给正面的目标表达和例子、明确哪些资料不必重复。这些是实践经验，不是固定模型效果的保证。[S3–S5]

系统提示词本身也要有取舍。一份规则文档不必完整复制到所有角色。调查者需要保存依据，构思者需要提出新联系，编辑需要作出短判断，报告作者需要组织表达。Anthropic 的上下文设计建议同样强调信息要充分而有选择，避免把所有边缘情况塞进提示词。[S6]

## 9. 分开写作与编辑，但不要无限增加审核

用户提供的两路检查很有用。A 路只检查读者能否顺着读、哪些句子重复或没有功能；B 路对照原材料，检查改写有没有改变事实、条件、范围和未知。两路都不负责重新证明研究结论。

在开发阶段，可以让两位独立编辑分别看同一份原材料与改写稿，不看作者的自我说明，也不先看另一位的意见。将具体意见合并后修改一次，再核对被改动的部分。没有问题时直接结束，不要求每位编辑必须找到若干条缺陷。

不采纳“主模型自审永远无效”的绝对说法。自评偏差研究提示过自我偏好的风险，而 Self-Refine 在其他任务中报告了同一模型自反馈的收益。它们研究的模型和任务不同，都没有证明 ARC 必须新增两条常驻审核链。[S7–S8]

日常产品是否需要独立编辑，应由实际产出与成本决定。已有一次独立报告编辑时，优先改好它的任务和输入；不要每张卡额外运行两位审稿人再加裁决者。

## 10. 可直接复用的写作指令

```text
写给了解本领域基础、但尚未读过这份材料的研究同事。

先讲清楚当前问题和主要判断，再解释最必要的依据、具体做法与未知。用自然段让内容逐步前进，不把字段、检查表或操作日志逐项改写成正文。

保留原材料的事实、数值、单位、比较对象、定理前提、实验范围、未测范围和决定性未知。假设仍是假设，计划仍是计划。把必要条件放在相应结论附近，同一限制不用反复说。删去没有实质信息的让步、自我辩护和“经过检查所以可信”。

用具体对象和动作解释术语。一个段落围绕一个主要问题，保留需要的因果和转折。不要靠缩写、分号、括号和口号压缩内容，也不要为显得自然补造例子、经历或观点。

根据读者的任务选择深度：预研交代核心思路与进入路径，结果段交代观察与含义，方法细节放在相应部分。没有新内容就结束，不补重复总结。最终只交正文。
```

## 11. 改写例子

以下例子只用于说明表达方式，不是对某项研究结果的重新验证。

### 例一：用户提供的防御性句子

原句把结果、一致性和三个未测范围放在一条长句里。可以改为：

> 在已测试的攻击区间内，误差得到恢复，通信更新减少，与理论描述一致。更强攻击、其他系统规模和长期运行尚未测试。

如果未测范围已在相邻位置清楚交代，第二句可以并入那个位置；不能在整份交付中直接删除。用户示例中的“体现机制作用”也不能被当成额外的因果证据。

### 例二：把流程状态移出研究正文

改前：“上述内容经过多轮校验，全部检查项通过，因此本文结果可信。”

改后：“定理在给定假设下给出误差界；实验展示了所测设置中的误差和通信开销。”

只有原材料确实给出这个定理和这些实验时才这样写。若原材料只有流程记录，就写“现有记录只报告检查状态，缺少可转述的研究结果”，不能凭空补一条科学结论。

### 例三：把实验菜单改成一个问题

以下为虚构编辑示例。改前：“采用对象替换、布局扰动与多条件控制，设置全量重写、增量修复和运行时重查询，报告多维指标与失效归因。”

改后：“这个想法想区分两种失败：技能步骤本身过时，还是技能指向的物体变了。前者需要改技能，后者可能只需要重新找到对象。首先要弄清，维护一个持久绑定表是否比每次执行时重新查询更有必要。”

研究动作和关键参照仍然清楚，没有提前写成执行计划。

### 例四：保留局部条件，不写长免责声明

虚构原材料：“三种模型在固定成本设置下减少了无收益的提问；真实交互成本未测试。”

改后：“在固定提问成本的设置下，三种模型都减少了无收益的提问。真实交互中的成本变化还没有测试。”

不改成“该策略能高效处理各种交互成本”，也不用“尽管场景有限，但仍具有显著潜力”。

### 例五：发现近邻，直接更新认识

虚构原材料：“原以为这是新的技能维护机制，后来发现近邻已有同类机制；环境变化后的检索失配尚待查。”

改后：“技能维护本身已有近邻。这里剩下的问题是：环境变化后，仍然可用的技能会不会因为描述过时而检索不到？”

不要把“尚待查”改成“该问题确实广泛存在”，也不要回放所有检索与修订步骤。

## 12. 社区方法的取舍

| 来源 | 本指南采用的部分 | 不直接采用的部分 |
|---|---|---|
| 用户提供的双路编辑建议 | 句子功能与表达忠实分别检查；流程记录与科学内容分开 | 自审必然失败的断言；不看上下文就删去未测范围 |
| OpenAI 社区的表达与长度讨论 | 给具体读者、正面例子；消除重复栏目；把次要说明放到恰当位置 | 神奇 JSON 提示格式；固定三句适用所有题目；全面禁用不确定措辞 |
| `blader/humanizer` | 识别空转开场、重复结尾、假想反驳；按文体重写段落，保留事实 | 为“像人”新增反应或经历；给技术文献统一加口语口癖 |
| `hardikpandya/stop-slop` | 具体表达、减少套话、检查句子节奏 | 删除所有副词或被动句、禁止所有对比与破折号、按主观总分循环改写 |
| 学术写作与模型研究 | 组织信息供人理解；校准陈述强度；警惕自评偏好 | 把某模型某任务的结果当作所有模型的写作规律 |

本次没有找到用户所贴中文 Tips 的可确认原始发布页，因此将它作为用户提供的材料使用，不补造作者或出处。社区帖子中的未证实数字和关于模型“安全动机”的推测不作为依据。
