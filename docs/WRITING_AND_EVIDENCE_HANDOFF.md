# 成文报告与缺证交接

## 阶段成文

writer在阶段研究结束后处理一次报告，不调用检索，不改变研究判断。先说核心问题、现有方法实际做了什么、候选的新增认识和主要风险；术语首次出现时解释其操作含义。只选少量决定性文献，其余细节留在技术稿。

新任务输入包含写作上限：阶段摘要450字符、总览1100字符、每候选1300字符，每个自然段260字符，每份正文最多5条关键引用。提示词建议写得更短，上限用于发现明显超长输出。字符数包含汉字、英文、标点和公式文本，不是模型token数。

超限诊断列出字段、段号、实际长度与上限，使用原有一次JSON纠错机会；不直接截断正文，也不重跑调查。旧任务按原冻结输入验证，不追溯套用新字数要求。长度检查只能发现篇幅问题，不能证明文字已经清楚或科学结论忠实，真实阅读仍必要。

研究对象和原稿保留。运行中与离线渲染优先使用原任务冻结的Markdown资源，避免更新代码时把新模板与旧输出混用。需要重新成文时，应建立独立的文字修订任务及快照，保留原报告；明确指定的修订模板优先于历史模板。

## 关键来源无法访问时

无法读取关键全文，既不证明已有工作没有覆盖，也不必强迫每条线索无限等待。若scout的CHECK、DEVELOP或PRESSURE已经形成合法的lead/drop草稿，却因needs_evidence停在critical_source_unavailable，用户可以显式选择暂缓证据：

```bash
arc --env-file /path/to/existing/.env --data-dir /path/to/private/arc-data \
  retry-task RUN_ID --task-key idea5.check \
  --defer-evidence --reason "暂缓无法读取的全文；保留缺口，只交付有限线索。"
```

它创建新任务版本，复用原输入及已查材料。新结果必须重新完成、保持lead或drop，并明确未解决限制；不能通过此入口升级为discuss。原缺证响应、失败费用、证据请求和能力需求保留，不会被标成已解决。后续协议重试仍继承这一限制。若连有限判断也无法诚实形成，任务可以继续保持暂停。

代码只检查有限状态与明确的限制字段，是否准确保留关键缺口仍需语义判断。这个选择由正式用户作出，CodeX只在本轮获授权的开发验证中代为操作。完整原始记录保存在私有数据目录，不放入公开报告或仓库。
