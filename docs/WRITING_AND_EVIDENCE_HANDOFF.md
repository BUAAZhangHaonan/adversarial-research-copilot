# 成文报告与缺证交接

## 阶段成文

writer 在阶段研究结束后，根据保存的当前认识做一次润色。主卡先用具体场景说明研究问题，再解释最近工作、核心设想、可行性依据和价值；术语首次出现时说明其操作含义，未验证关系明确写成待检验设想。详细风险、证据范围和必要比较写入独立技术分析，与完整科学记录一同保留。writer 不新增检索，也不改变候选去留判断。

篇幅由独立 Markdown 提示词引导。字符数、词数、段落数和单段长度不触发拒收、截断或重写；旧冻结输入中的长度配置也不用于拒收完整响应。模型原文与原始 JSON 继续保存。

仍检查 JSON 和必要字段、候选身份覆盖及重复身份、引用来源归属与目录范围，每份正文最多 5 条关键引用。结构通过不代表科学质量通过，需要核读具体问题、研究增量、可行性依据与结果解释。

研究对象和原稿保留。运行中与离线渲染优先使用原任务冻结的Markdown资源，避免更新代码时把新模板与旧输出混用。需要重新成文时，应建立独立的文字修订任务及快照，保留原报告；明确指定的修订模板优先于历史模板。

## 关键来源无法访问时

默认 discover，以及从轻量候选进入的 develop/run，遇到关键文献不可用或反复读取没有新内容时，自动创建一次有限收尾任务。它复用冻结输入、已读片段和原缺证草稿，不再调用工具。CHECK、DEVELOP、PRESSURE只能交付lead或有证据支持的drop，并写明未解决问题；缺证本身不能作为放弃研究问题的理由，更不能升级为discuss。

有限收尾仍有原有的一次JSON纠错。如果仍缺证或输出修复失败，该候选标为“文献受限，保留待查”，不接收失败稿；其余候选继续。SURVEY完全无法形成判断时，只保存明确的资料不足说明；不会捏造领域结论。原响应、费用、未决证据与能力请求保留，恢复运行复用同一个任务键，不重复请求原失败任务。

这项自动续行仅处理文献访问问题。模型响应未知、费用结算异常、预算未获准或任务环境不一致仍按原机制处理。科学判断是否准确，仍需要阅读材料与结果；流程完成不能证明证据齐全。

历史任务的人工暂缓入口仍可用：

```bash
arc --env-file /path/to/existing/.env --data-dir /path/to/private/arc-data \
  retry-task RUN_ID --task-key idea5.check \
  --defer-evidence --reason "暂缓无法读取的全文；保留缺口，只交付有限线索。"
```

旧完整研究卡流程保持原来的显式重试语义。当前默认轻量流程无需CodeX或用户逐次批准缺证收尾；正式运行中的新增工具能力需求仍交给用户评估和实现。

2026-09-13 写作改造将共同规范接入七个角色任务。当前认识置于正文，旧标题、撤回前提、修改经过与详细条件留在技术记录；不通过正则或新审核角色判断科学结论。参见[写作指南](RESEARCH_WRITING_GUIDE.md)与[实施记录](writing_review/PROMPT_IMPLEMENTATION.md)。
