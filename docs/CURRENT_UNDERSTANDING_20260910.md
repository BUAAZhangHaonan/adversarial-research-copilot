# 2026-09-10：让预研认识进入下一次抽卡

保留共享调查 → 短灵感 → 价值初筛 → 入围预研 → 人选择的主干。本次不新增科学审查角色、不恢复完整研究卡流水线、不重跑旧十卡或模型消融。

## 功能与研究边界

| 审阅问题 | 当前实现 |
| --- | --- |
| 预研只追加笔记，旧概述仍在 | CHECK 输出 current_understanding；发现共享叙事失效时，只替换 field_revision 指明的 overview、research_lines、openings。旧简报另存历史，来源笔记按本次实质更新替换当前版本。 |
| 下一次仍使用初稿印象 | SKETCH、TRIAGE、CHECK 的 previous_directions 从已保存记录实时形成，含最终决定、查后核心认识、撤回前提及决定性未知。恢复时排除当前候选自身。 |
| 档案查回 investigate，却看不到最后 drop | 检索返回最终 note 的当前视图；索引包含修正内容。旧记录从实际最终理由和改动形成兼容视图，不凭空生成新科学判断。初稿仍可完整读取。 |
| 编辑看不到本轮候选 | TRIAGE 显式收到本轮其他候选的最新简短认识，并说明独立问题、替代路线、评估支撑或重叠关系。没有相似度一票否决或规定淘汰率。 |
| 查到近邻后不断加条件保卡 | CHECK 要回答去掉已覆盖部分后剩下什么，以及新增条件为何使已有方法不足。解释不了时保留线索和决定性未知；不把未做实验当作自动淘汰理由。校准例子包含常规扩展与有实际机制差异的条件。 |
| 重复读已有缓存 | 共享 SourceNote 足够时可直接复用；元数据不算已读材料。记录区分 task_read / shared_notes / unverified，报告不会把输入复用算成新增工具动作。 |
| 报告仍先展示过时seed | 首页和候选详情先显示当前认识；初稿明确保留为历史。有记录才呈现候选关系，并突出主要未知及撤回前提。 |

新任务要求 current_understanding 与 candidate_relation，遗漏进入现有一次 JSON 纠正。旧数据保持可读，不批量改写旧模型输出。field_revision 可以为空，不强迫每个候选改写整份简报。所有研究判断仍可能出错，功能接通不代表自动选题已获科学认证。

## 人工阅读边界

本轮验证确认更新被保存、传递、召回和呈现，没有独立复核所有新近邻，也不把discuss当作最终选题。真实产物仍有过度概括与冗长段落，需要人的研究判断。例如新概述将CausalWorld称作“非具身操作域”并不准确：[原论文](https://arxiv.org/abs/2010.04296)明确是机器人操作环境；可以区分操作与导航，不能据此声称具身领域没有相关干预基准。该提醒是CodeX交付阅读核对，非Agent自主纠错成果；原模型响应与费用原样保留，交付报告附同一阅读说明。

本次不为修整这张已审阅开发卡再启动多轮科研验证。后续用人的选题反馈判断核心价值，避免把抽卡系统开发变成自动证明所有候选正确的项目。
