# 64000 字符读取实施说明

本项已按用户选择实施，2e152b4 在 master 启用 read_record 单次 64000 字符上限；默认仍为 12000。此前未启用是开发安排上留作可选支线，不是已经确认存在技术障碍。

原始需求 `cap_arc-vnext-validation-20260907.natural_tool_correction_v1.develop.user.64k.review` 与旧评估保留在私有需求档案和 Git 历史。本文件不再包含已失效的“待用户启动”步骤。

## 范围

64000 是字符数，不是 token 数。只改变 read_record 的公开 schema 和对应说明；原文、来源、version、字符 offset、缓存覆盖信息保持原语义。模型、reasoning_effort、max_tokens 及预算规则没有改变。

## 已完成验证

- 实际 build_tools 和 Runtime 回归使用包含中文及 emoji 的原文，核对 64000 字符窗口与原文切片完全一致，来源元数据及原始全文不变。
- 64001 在执行前拒绝，反馈上界后可以使用工具参数纠错机会改成 64000。
- 预算暂停后重建 Runtime 并恢复，成功读取和已结算模型调用不重放；最终预留为零。
- 断言模型请求仍为 max、max_tokens=384000；最终 JSON 与工具参数纠错分别计数。
- 远程完整测试402项和仓库外独立安装检查通过；wheel 加载到的公开上限为64000。

本轮真实定向补证已成功请求并获得 30000 字符窗口，超过旧的 24000 上限。后续缓存末尾空读被保留为正文尚未完全取得的限制，没有把缓存读完等同于原文全部读完。精确 64000 边界、预算暂停和恢复由上述离线回归验证。

更大的页可能减少交互，也可能增加上下文。上述验证证明边界、分页和恢复正确，不证明模型质量或费用必然改善。真实使用情况与最终阶段结果见 [MASTER_STATUS.md](MASTER_STATUS.md)。
