# ARC 功能改版验收结果（草稿）

更新：2026-09-08。目前完成的是**已知硬错误的发现、定向修订与复核**；还不能据此认定新 idea 质量已提高。

## 已完成：四组成对科学纠错

v2 的八个真实模型案例全部结束。按预设目标逐项核对，**8/8 达到本轮纠错验收要求**：四个错误版本均发现目标错误并保存了实际修订；四个正确版本均未被捏造同一目标硬错误。这里的 8/8 是八个对照案例，不是八种错误，也不代表八张卡值得研究。

| 对照组 | 正确版本 | 错误版本的实际修订 | 修订后版本 |
| --- | --- | --- | --- |
| 原问题与测试总体 | 无目标硬错误，不强制修订 | 从只测一致单元改为在冲突单元比较；一致单元仅作实现校验 | v1 → v2 |
| 数字归属 | 保持未压缩 62%、压缩 71% | 动机及 claim 中的反向归属改正；补证后再次审查 | v1 → v3 |
| 交互基线 | 四条件齐全，无目标硬错误 | 把未处理条件 `(0,0)` 从可选改为必测，交互公式各项均有观测 | v1 → v2 |
| 分母与类别穷尽性 | 保留包含成功类的完整分解 | 加入合格率，明确三种失败率之和为 `1 − 合格率` | v1 → v3 |

上述错误版本最终均为 `routine / reject`。这表示**错误修好了，但研究价值仍属常规**，不是科学修订失败。正确版本不因研究价值普通而必须修改。验收依据包含初审具体理由、最初与最终卡片、修订复核和真实保存版本，不能仅以输出字段、状态码或 `resolved` 标签计通过。

## 仍须如实保留：一次研究价值高估

v2 case5（正确的四条件交互卡）最初被评为 `substantial / retain`。理由主要是该合成系统的交互值尚未知、测完能回答原题；这不足以说明结果会改变重要解释、方法选择或边界认识。因而它通过了“没有硬错误”的检查，却暴露了**把普通未知事实高估为重要研究问题**的缺口。

随后补充价值校准，使用同一张已见正确卡进行 value-v3 真实复核。结果为 `routine / reject`，`decisive_findings=[]`：模型保留正确设计，指出其缺少具体决策后果，没有为了拒绝而编造科学错误。

这是一次已知案例上的校准修正。v2 的原始 `retain` 记录保留；value-v3 不能替代 v2 原始结果，也不能当作未见主题泛化或科研品味整体提高的证据。
