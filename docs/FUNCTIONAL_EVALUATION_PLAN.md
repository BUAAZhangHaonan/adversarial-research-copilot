# 功能重构验证安排

本轮优先验证科学错误能否被发现、修正且不误判正确版本，再评估核心构思质量。软件契约通过不等于研究质量提高；匿名模型偏好不能代替原文与逻辑检查，也不能单独宣布抽卡收益。

## 先验证纠错连接

`tests/fixtures/scientific_error_pairs.json` 保存四组成对合成材料，共八张短卡：原题条件保留/被移除、方法数字归属正确/对调、交互所需基线完整/可选、全实例分类闭合/漏掉成功类。每组只有目标内容不同，共用原始问题和材料。`model_visible` 是可传给模型的唯一输入，`expected` 只供开发验收。`tests/helpers/scientific_cases.py::model_payload` 返回隔离副本；不要把 case_id、文件名、正误标签、验收答案或同组另一版本塞入正式提示词。

先独立审查八张卡，记录具体发现而非只记 retain/reject。正确卡可以普通、没有外部新颖性；这种价值判断不算误判。误判指无依据地认定本例目标硬错误存在。错误卡需定位原句/字段、给出材料或反例、解释后果；存在目标错误仍被保留算漏检。

对可修错误使用同一卡的定向子节更新与 claim 更新，随后独立复核。验收分别记录：目标错误是否找到、修订是否实际改掉原句与依赖推论、复核是否接受有效纠正，以及是否引入新硬错误。失败和无法完成的修订完整保留，不用重抽一个较好候选代替。该集合验证开发纠错连接，不验证新 idea 价值，更不是未见留出。

## 再比较生成与审核

| 条件 | 生成 | 审核 | 修订 | 主要比较 |
| --- | --- | --- | --- | --- |
| A | Pro 连贯构思 | 历史审核 | 无 | 基准 |
| B | Pro 分步构思 | 历史审核 | 无 | A/B：分步构思作用 |
| C | Flash 分步构思 | 历史审核 | 无 | B/C：构思模型作用 |
| D | 复用 A 的同一 Pro 候选 | 新科学审核 | 无 | A/D：审核差异 |
| E | 复用 A/D 的同一 Pro 候选及 D 审查 | 新科学审核 | 定向修订与复核 | D/E：纠错转化 |

历史审核须显式使用 `PromptLoader(tests/fixtures/prompts_pre_redesign)` 中保存的原始模板。当前生产 novelty/selector 已重写，不能把它们称作旧审核。所有条件直接收到相同原始任务和关键条件；分步生成的 FRAME mandate 要传入写卡和之后判断。A、D、E 不得各自重新调用 Pro 生成一张不同卡；缓存并复用相同初始候选，保留各分支输出。各路径生成模型、步骤、实际工具材料、审核模板与真实费用分别记录。

`run_comparison(..., seed=..., include_swapped_order=True)` 提供同一候选的两序匿名评价；两序有独立任务结果及私有身份映射。该开关只追加评价，不重抽候选。不同 seed 是不同展示序记录，不自动等于独立生成重复。独立生成重复要显式采用新的任务身份并保留全部输出，不能只挑每条路径表现最好的一次。已有历史冻结比较仍是原来的发现阶段对照，不可重新命名为完整 A–E 消融。

### 公开 CLI

在仓库根目录执行以下命令，替换运行 ID、实验 ID 和已授权父账本 ID。`test-compare` 默认 seed 为 `20260907`，默认执行两个展示次序；显式加 `--no-swap-order` 只运行正序。恢复同一 seed 会复用已有任务。

```bash
arc test-compare --source-run SOURCE_RUN --seed 20260907 --swap-order
```

`test-ablation` 要求显式指定五个执行参数。`--budget-cny` 是每个条件/评价子账户的上限，所有账户共同受 `--parent-budget` 指定的现有父账本限制；该命令不会新授权父级额度。A–E 与匿名评价由既有 harness 串行执行。使用相同实验 ID 和相同参数恢复冻结实验，不能借恢复更换原始材料或展示 seed。

```bash
arc test-ablation --source-run SOURCE_RUN --experiment-id ablation-01 \
  --parent-budget AUTHORIZED_PARENT --budget-cny 20 --seed 20260907
```

历史 prompt 目录默认是当前工作目录下的 `tests/fixtures/prompts_pre_redesign`；从其他目录执行或使用另一份明确冻结的历史快照时，传入 `--legacy-prompt-root /absolute/path/to/prompts_pre_redesign`。目录不存在或缺少 `manifest.json` 会在启动 harness 前明确报错，不查找其他目录代替历史模板。完整模板内容仍由 PromptLoader 验证。

## 材料、费用与结论范围

已有渲染、分割、冲突三个主题都进入开发回归；它们被反复分析，不能继续叫未见留出。下一步迁移测试使用新主题，先固定用户问题和材料，再生成全部预定条件，不根据看到的输赢更换主题或筛除失败。

所有付费模型调用串行，继续使用现有父账本及用户已授权余额；本轮规划起点剩余额度上界为 **200.602047 CNY**，实际可用空间须以启动时账本为准，不新增额度、不重置历史费用。该数是授权内账本估计，不是再次查询供应商余额。预算是上限，不为等成本强行消费。保留 DeepSeek V4 Flash/Pro、max 思考配置，不同时调整无关参数。本计划本身不启动任何付费调用。

顺序为成对纠错验证 → 生成/模型/审核消融 → 新主题迁移 → 真实 discover → develop → run。若纠错连接仍有普通实现缺陷，先修复并在同一验证口径下继续；不能用跑通长链替代修好错误的证据。最终分别报告硬错误、正确卡误判、实际修订、核心洞察与人工可读价值，不把一项通过包装成整体提升。
