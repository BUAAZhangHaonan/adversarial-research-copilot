# request_capability

Record a research-tool capability that is missing from the actually registered tools. Describe the blocked question, desired inputs, required original-source/provenance outputs, cost visibility and acceptance example. This creates a requirements record only. It does not install tools, change MCP services, grant new permissions or complete the blocked research action. Continue only with independent work that existing tools and evidence genuinely support.

## Improvements to an existing capability

You may also request an improvement to an existing tool or workflow, such as evaluating
a larger read_record page limit. State the observed current_limitation, a concrete
proposed_change, the rationale, available alternatives (including continuing within
the current limit), and expected_impact on research, execution and cost. Keep the
original blocked question, operation, inputs, output, provenance, cost visibility and
acceptance example explicit. Do not claim an unobserved limit or imply that a proposal
has been implemented.

A successful call means the request was recorded as pending_codex_review. CodeX can
assess its reasonableness and recommend an option in a separate review. The resulting
handoff is text for the user to choose whether to execute; it creates no Codex task.
Recording or reviewing a request does not increase a limit, authorize spending,
install a tool or change a service. Existing execution limits still apply.
